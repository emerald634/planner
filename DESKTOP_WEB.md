# Desktop-web «План дня»: локальная оболочка

Дата: 21.10.2026. Ветка `feature/desktop-web-shell` от main `469344c`.
Это **визуальный прототип**, не production-приложение с работающим входом.
Он не объединён с 2.1.1 и не подключён к FastAPI, Telegram, Bitrix24 или SQLite.

## Структура и изоляция

`miniapp/desktop/` использует уже зафиксированные React/Vite/TypeScript/Playwright
из Mini App, без новых зависимостей, копий API-клиента или backend-бизнес-логики.
Типы Employee/Plan/Task импортируются из существующих `miniapp/src/types.ts`.
Отдельные Vite config/tsconfig, HTML и dist сохраняют обычную сборку Mini App.

- `src/theme.css`: дизайн-токены, тёмный фон, карточки, боковое меню, адаптивность.
  Подготовлены переменные будущей светлой темы, переключатель не реализован.
- `src/App.tsx`: навигация, личный обзор, планы/задачи только для чтения, показатели,
  два обзвона-заготовки, обзор отдела, сотрудники, демонстрация согласований.
- `src/metrics.ts`: независимые определения шести метрик, единицы/период/норма/
  источник/дата актуальности; факт и время обновления null, нет фиктивных нулей.
- `src/fixtures.ts`: исключительно вымышленные Алексей/Мария и их планы.
  История, отчёты и настройки показывают честные пустые состояния.
- `demo.html`/`src/demo.tsx`: только dev, режим desktop-demo и loopback. Переключение
  ролей — просмотр вымышленных экранов, не способ серверной авторизации.
- `index.html`/`src/main.tsx`: production entry показывает закрытый экран без
  входа/данных. Не импортирует App/fixtures, не имеет выбора ролей, запросов API
  или формы, создающей ложное впечатление работающего входа.

У dev-сервера нет proxy, envDir отключён, host 127.0.0.1, /api отвергается.
CSP ограничивает demo-соединения локальным origin/HMR; production entry запрещает
сетевые соединения. Это локальная изоляция прототипа, не доказательство будущей
серверной авторизации. Не публиковать demo-сервер в интернет и не копировать
demo-файлы в production. Обычный build Mini App не импортирует эту директорию.
Planner release allowlist также не включает её.

Таймер показывает готовый elapsed_seconds из вымышленного серверного снимка,
не запускает собственный интервал и не начисляет время. Изменения плана, пауза,
подтверждение и решения не отправляются; соответствующие действия отключены.
Будущий web использует тот же серверный таймер, ревизии, защищённые цели и API.

## Просмотр

Из `miniapp`, с существующими зависимостями из pnpm-lock.yaml:

```powershell
pnpm run dev:desktop
```

Открыть **http://127.0.0.1:5174/demo.html**. Роли переключаются в верхней полосе
«ДЕМО». Если порт занят — не останавливать чужой процесс. Здесь strictPort.

```powershell
pnpm run build:desktop
pnpm run preview:desktop
```

http://127.0.0.1:5175/ показывает только закрытый production entry. Никакая
рабочая веб-авторизация ещё не реализована; сборка сознательно не выдаёт demo
за готовую production-версию. Выход — `miniapp/desktop/dist`, исключён из Git.

Для браузерных проверок нужны одновременно dev и preview на этих loopback-портах:

```powershell
pnpm run test:desktop
```

Скриншоты обеих ролей в 1366×768, 1440×900, 1920×1080:
`test-artifacts/desktop/`. Исходные изображения утверждённого макета и полная
памятка продаж в доступной папке не найдены; реализовано текстовое описание.
Финальное визуальное соответствие и правила адаптации новичков требуют сверки.

## Достоверность показателей

Нормы из текущего задания: 35 честных наборов/день; 8 дозвонов от минуты/день;
12 консультаций от 10 минут/неделю; 15 клиентских разговоров от 2 минут/неделю;
80% первых звонков до 15 минут; 90% перезвонов в ±15 минут.
Начало действия 01.11.2026, не задним числом. Месячные/недельные пересчёты и
снижение норм новичкам не выдуманы и не автоматизированы. Периодичность двух
процентных целей не определена в задании: модель хранит unspecified, интерфейс
просит уточнение, дневная/недельная норма не выдумывается. Поддержаны выбор периода/даты и недоступность.
Личные нормы не складываются в норму отдела; выбранный менеджер показан отдельно.
CRM-факт, источники событий, «честность» попытки, дедупликация звонков и нормы
отдела ещё требуют спецификации. Неподключённые показатели показывают «Нет данных».

## Что можно переиспользовать после авторизации

Существующие /api/me, /employees, /plans и detail, /tasks/{id}, /timer,
/confirm, /approve, /requests и /decision, /history, /report, /distributions.
Сейчас они требуют Telegram initData: cookie web им ещё не подходит и demo
их не вызывает. Будущий общий сетевой слой должен сохранить deadline JSON,
валидацию, отмену, защиту контекста и запрет автоматического повтора мутаций из
Mini App; auth-transport выбирается явно. Бизнес-правила остаются на FastAPI.
Детальный проект входа и security-тестов: `WEB_AUTH_ARCHITECTURE.md`.
