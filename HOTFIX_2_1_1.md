# Хотфикс 2.1.1 — локальная разработка и проверка

Дата: 14.10.2026. Изменения ограничены frontend и тестовыми средствами.
Production/Ubuntu/Docker/Nginx/Telegram-бот/рабочие базы/.env не изменялись.
Новых функций 2.2 и миграций нет; backend схемы 4 остаётся прежним.

## Исправление

App.tsx больше не объединяет сотрудников, планы, согласования и уведомления
одним Promise.all. Каждая независимая загрузка применяет свой результат и
сохраняет свою ошибку. История также не блокирует отображение плана. Запрос
выбранного плана по-прежнему зависит от корректного списка планов.
Обновление/действие не ждёт уведомлений или сотрудников, чтобы показать план.

Список сотрудников отображается сразу после его ответа. До первого ответа
показывается «Загрузка сотрудников», при отказе — «Сотрудники не загружены»,
а не фиктивный ноль. Ранее успешно полученные данные при временном сбое не
удаляются, но отдельное сообщение ошибки остаётся видимым.
Для каждого раздела есть «Повторить загрузку» только этого ресурса.
Ошибка планов не выдаётся за отсутствие планов; ошибка согласований/истории
не выдаётся за пустой список. Периодическое обновление не стартует новую
загрузку планов, пока предыдущая ещё выполняется.

Ответы проверяются по контексту и номеру загрузки: поздний ответ предыдущего
выбранного менеджера не заменяет актуальный план. История повторно загружается
по ID актуального выбранного плана из ref, без циклических эффектов React.

api.ts: AbortController и Promise.race ограничивают запрос **15 секундами**,
включая response.json() для успешного и ошибочного HTTP-ответа. JSON validation
не даёт объекту/HTML/неполным записям попасть в состояние, где ожидается массив.
response.ts проверяет me/employees/plans/detail/report/requests/history/
distributions и основные ответы операций. Дополнительные поля допускаются;
это проверка структуры для UI, не замена серверной авторизации.

Сохранения не повторяются автоматически. При таймауте POST/PATCH сообщение
предупреждает о возможном commit и предлагает сначала обновить данные.

## Проверки

- 142 Python-теста успешно, только временные базы и mock CRM.
- node tests/hotfix-api.cjs успешно: malformed JSON/структура, HTTP/network,
  зависший fetch, зависшее чтение успешного и ошибочного JSON, AbortSignal.
- TypeScript и production Vite build успешно.
- Edge ui-hotfix.cjs: другой активный supervisor (искусственный Telegram ID),
  прежний supervisor отключён; два менеджера отображаются, выбор сотрудника,
  планы, pending notifications/body timeout не блокируют UI, HTTP503/malformed
  response показывают scoped error, retry восстанавливает раздел. Проверены
  начальный текст загрузки сотрудников, быстрый выбор другого менеджера и
  таймер менеджера при недоступных уведомлениях. Page errors отсутствуют.
- Edge ui.cjs: прежний supervisor, оба менеджера, таймер, согласование цели,
  перенос обычной задачи, закрытый отчёт и manager confirm — успешно.
- Edge ui-distributions.cjs: автоматический импорт, источник задания,
  подтверждение менеджером, таймер и supervisor review — успешно.
- pip check успешно. API/front-end тесты используют только искусственные токены.

В browser/API тестах дедлайн ускорен только в тестовой среде. В production
всегда 15000 ms. Сбой воспроизведён искусственно; **конкретная первопричина
production-инцидента и вина /distributions не установлены**. Исправлен
подтверждённый дефект связывания независимых загрузок и отсутствия таймаута.

## Ограничения

Фактические ответы production API не получали; ошибки его данных/схемы/доступа
этот frontend-патч не исправляет, но показывает их по разделам вместо общей
блокировки. Реальные Telegram-клиенты Mac/iOS ещё требуют проверки после
отдельно согласованной установки. При таймауте операции сохранения результат
неизвестен до обновления; серверные ограничения/ревизии продолжают действовать.
Правила доступа и роли не ослаблялись и не менялись.

Локальный frontend-кандидат 2.1.1 может храниться отдельным архивом с готовым
dist, новым frontend-build.json и исходниками хотфикса. Это **не полный Docker
релиз**: нельзя распаковать его поверх прежнего production-каталога, где общий
release-files.json описывает старые файлы. Подготовка полного серверного релиза
и установка требуют отдельного разрешения. Релиз 2.1 и его архивы сохранены.
